# CodeDiff Git Flow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Sourcetree's Git Flow menu to CodeDiff: initialize, start and finish features, releases and hotfixes, a Next Action panel, and an optional push at the end of Finish Release / Hotfix.

**Architecture:** Flow logic is pure functions over `git2::Repository` in two new core modules (`flow`, `flow_finish`) that return plain data. A third module (`push`) runs the installed `git` for the one network step. The existing worker thread gets new `Command`s and `Event`s; the UI bridge maps them onto a new Slint global `Flow`, which drives a menu, three dialogs and a third mode of the existing search panel.

**Tech Stack:** Rust 2021, Slint 1.18, git2 0.21 (built without network transports, keep it that way), the system `git` for push only, tempfile for tests.

**Spec:** `docs/superpowers/specs/2026-11-16-git-flow-design.md`. Mockups (local only): `.superpowers/brainstorm/51052-1794818570/content/gitflow-screens-v3.html`.

## Global Constraints

- Local Git Flow steps use `git2` only. The `git` command line is used for the push and nothing else.
- No fetch, pull or commit UI. The only push is the optional one at the end of Finish Release / Hotfix. Finish Feature never pushes. Only the `origin` remote.
- Push is `git push --atomic`, never a forced update of a branch or tag. The remote branch delete carries a lease on that one reference.
- Finish is all or nothing: if a local step cannot complete, no branch, tag or HEAD has moved and the working tree is untouched. Never call `Repository::merge` (it writes merge state and conflict markers).
- Git Flow settings use the standard local config keys `gitflow.branch.master`, `gitflow.branch.develop`, `gitflow.prefix.feature|release|hotfix|versiontag`, plus `gitflow.prefix.bugfix = bugfix/` and `gitflow.prefix.support = support/` written on init.
- Defaults: `develop`, `feature/`, `release/`, `hotfix/`, no tag prefix. Production defaults to `main`, else `master`, else the current branch.
- Git work never runs on the UI thread.
- Flow dialogs: Return runs the primary action when enabled, Esc cancels, clicking outside does nothing.
- Every new color gets a dark and a light value in `ui/theme.slint`.
- Never use the em dash character in code, comments, docs or commit messages. Never add a Co-Authored-By line to commits.
- Known failing test, unrelated and out of scope: `start_does_not_scan_large_trees` in `tests/watch_test.rs`. "All tests pass" below means all except that one.

2. **The repository changes between opening the dialog and clicking Finish** (an agent commits or edits). Expected: Finish re-checks, refuses, changes nothing, and the dialog shows the new blocker. Tests: `finish_refuses_when_blocked_and_changes_nothing` (Task 5), `flow_finish_blocked_emits_failed_and_plan` (Task 7).

`flow_state` now fills `latest_tag` (None when not initialized).

`start_error` messages, checked in this order: `"Enter a name."` (empty); `"Not a valid branch name."` (whitespace, leading or trailing `/`, or `git2::Branch::name_is_valid` false for prefix plus name); `"{branch} already exists."`; `"{branch} already exists on origin."` (reference `refs/remotes/origin/{branch}`); `"Tag {tag} already exists."` (release and hotfix, tag is version tag prefix plus name); `"A release is already open: {branch}."` / `"A hotfix is already open: {branch}."`.

Action keys and copy:

| key | name | detail |
| --- | --- | --- |
| `init` | Initialize repository | Set up Git Flow branches and prefixes |
| `finish:feature:{branch}` | Finish feature {name} | Merge into {develop} |
| `finish:release:{branch}` | Finish release {version} | Merge into {production} and {develop}, tag |
| `finish:hotfix:{branch}` | Finish hotfix {version} | Merge into {production} and {develop}, tag |
| `finish:feature` | Finish feature… | Pick a feature to merge into {develop} |
| `start:feature` | Start new feature | Branch from {develop} |
| `start:release` | Start new release | Branch from {develop} |
| `start:hotfix` | Start new hotfix | Branch from {production} |

Order: the finish row for `state.current` first, with `" · current branch"` appended to its detail; then finish rows for an open release and hotfix that are not current; then `finish:feature` when any feature exists and the current branch is not a feature; then the start rows, leaving out release or hotfix when one is open. Not initialized: only `init`.

```rust
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct FinishRequest {
    pub kind: FlowKind,
    pub branch: String,        // full local name, e.g. "release/1.2.0"
    pub tag: String,           // "" for a feature
    pub message: String,       // tag message, "" for a feature
    pub delete_branch: bool,
    pub push: bool,            // ignored for a feature
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Blocker {
    Dirty(usize),                                   // changed tracked files
    Busy,
    NoIdentity,
    OtherWorktree { branch: String, path: PathBuf },
    BehindOrigin { branch: String },
    TagInvalid,
    TagExists(String),
    Conflict { target: String, branch: String, files: Vec<String> },
    Collision(Vec<String>),
}
impl Blocker {
    pub fn title(&self) -> String;
    pub fn body(&self) -> String;
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Step { pub text: String, pub note: String, pub remote: bool }  // remote: runs on origin

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct FinishPlan { pub steps: Vec<Step>, pub blocker: Option<Blocker> }

pub fn plan_finish(repo: &Repository, cfg: &FlowConfig, req: &FinishRequest) -> Result<FinishPlan>;

// tests/common/mod.rs, reused by Tasks 5 to 7
pub fn feature_req(branch: &str) -> FinishRequest;   // kind Feature, tag and message "", delete_branch true, push false
pub fn release_req(branch: &str, tag: &str, message: &str) -> FinishRequest;   // kind Release, delete_branch true, push false
```

Blocker copy (checked in this order, first hit wins):

| Blocker | title | body |
| --- | --- | --- |
| `Dirty(n)` | `{n} uncommitted changes` (`1 uncommitted change`) | Finish needs a clean working tree. Commit them, or discard them in Changes, then try again. |
| `Busy` | Repository is busy | A merge, rebase or cherry-pick is in progress. Finish it first. |
| `NoIdentity` | Git identity not set | Set user.name and user.email in Git config, then try again. |
| `OtherWorktree` | `{branch} is checked out in another worktree` | `{path}. Switch that worktree to another branch first.` |
| `BehindOrigin` | `{branch} is behind origin` | `Pull {branch} first, then finish again.` |
| `TagInvalid` | Tag name is not valid | Pick another tag name. |
| `TagExists(t)` | `Tag {t} already exists` | Pick another tag name. |
| `Conflict` | Cannot merge cleanly | `{target} and {branch} both changed these files. Nothing was changed. Merge {target} into {branch} first (agent or terminal), then finish again.` |
| `Collision` | Untracked files are in the way | Move or delete them, then try again. |

Rules: `Dirty` counts distinct tracked paths with staged or unstaged changes; untracked files do not count. `OtherWorktree` covers develop, production (release and hotfix) and the finished branch when it will be deleted, checked out in a worktree other than this one. `BehindOrigin` covers develop, production (release and hotfix) and the finished branch: blocked when `refs/remotes/origin/{b}` exists and the local branch is behind it by one or more commits. `Conflict` runs every merge in the plan with `Repository::merge_commits`. `Collision` is a dry-run safe checkout of the final develop tree, reporting conflicting paths.

Step text, in order. Feature: `Merge {branch} into {develop}`, `Delete {branch}` (when ticked), `Switch to {develop}`. Release and hotfix: `Merge {branch} into {production}`, `Tag {production} as {tag}`, `Merge {branch} back into {develop}`, `Delete {branch}` (when ticked), `Switch to {develop}`, `Push {production}, {develop} and tag {tag} to origin` (when `push`), `Delete {branch} on origin` (when `push`, `delete_branch` and `refs/remotes/origin/{branch}` exists). The first merge step's `note` is `{n} commits` (`1 commit`) counting `target..branch`, or `already merged` when the target already contains the branch. Other notes are empty. `remote` is true for the push step and the remote delete step, false for the rest.

Behavior:
- `find_git()` is called once, on the first repository open, and kept on the worker. `Event::Flow` is emitted from `open_repo` and `refresh`, only when it differs from the last one sent for that repository.
- `FlowInit`: `Ok` gives refresh then `FlowDone("")`. `Err(CheckoutConflict)` gives refresh, `FlowDone("")`, then `Event::Error` with the message (initialization stands). Any other error gives `FlowFailed`.
- `FlowCheckStart`: replies `FlowStartCheck` with `start_error`.
- `FlowStart`: `Ok` gives refresh then `FlowDone("")`; error gives `FlowFailed`.
- `FlowPlan`: replies `FlowPlan`.
- `FlowFinish`: error gives `FlowFailed(message)` followed by a fresh `FlowPlan` for the same request. `Ok`: for release and hotfix call `set_push_default(req.push)`; refresh; without a `PushSpec` emit `FlowDone(notice)`; with one, emit `FlowPushing`, run `push` on the worker thread, then `FlowDone(pushed_notice)` or keep the spec and both notices as the pending push and emit `FlowPushFailed(reason)`.
- `FlowRetryPush`: `FlowPushing`, push the pending spec again, same outcomes. `FlowDropPush`: forget it and emit `FlowDone(notice)`. Opening another repository forgets it.
- All of these do nothing when no repository is open or (except `FlowInit`) Git Flow is not initialized.
