# CodeDiff Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build CodeDiff, a lightweight macOS app (Rust + Slint) for reviewing local Git changes and history side by side, with file and hunk level stage, unstage, and discard, shipped as a `.dmg`.

**Architecture:** One crate, `codediff`, with a library (`src/lib.rs`) holding all Git, diff, highlight, watch and controller logic, and a thin binary (`src/main.rs`) that wires the Slint UI to the controller. All Git and diff work runs on one background worker thread that owns the `git2::Repository`; the UI sends `Command`s over a channel and receives `Event`s via `slint::invoke_from_event_loop`. Everything below the UI is tested headless against throwaway repos created with `git2` + `tempfile`.

**Tech Stack:** Rust (stable, 2021 edition), Slint 1.x, git2 0.20, notify 8 + notify-debouncer-full 0.5, syntect 5, similar 2, rfd 0.15 (folder picker), serde + serde_json 1, dirs 6, thiserror 2, tempfile 3 (dev).

**Spec:** `docs/superpowers/specs/2026-11-11-codediff-design.md`

## Global Constraints

- App name: CodeDiff. Binary, crate and bundle id: `codediff`, `com.codediff.app`.
- macOS first, Apple Silicon target. Avoid macOS-only code where a portable option is equally good (only packaging is macOS-specific).
- No dependency on the `git` CLI at runtime. All Git access through `git2`.
- No commit, amend, branch switch, checkout of refs, merge, rebase, revert, cherry-pick, stash, push, pull, fetch, or file editing anywhere in the app.
- Discard never runs without a confirmation dialog that names the file (and hunk) and says it cannot be undone.
- Diff display is side by side: old on left, new on right.
- History is read only.
- Git and diff work never runs on the UI thread.
- Performance targets: cold start under 1 s, idle memory under 100 MB, refresh after an agent write burst under 300 ms on a typical repo (up to about 100k files).
- Large diff threshold: a file diff over 5,000 lines or a blob over 2 MB shows "Large diff, click to load". History page size: 200 commits. Watcher debounce: 150 ms.
- Recent repos stored at `dirs::config_dir()/codediff/recent.json` (on macOS `~/Library/Application Support/codediff/recent.json`), max 10 entries, most recent first.
- Packaging: unsigned (ad-hoc signed at most) `.app` inside a `.dmg`. No notarization.
- Project text: never use the em dash character in code, comments, docs, or commit messages. Never add a Co-Authored-By line to commits.

## Review Focus

1. **Agent writes the file between render and click.** Expected: a hunk action on a stale view is refused with "File changed, refreshed. Try again." and the view refreshes; nothing is staged or discarded. Test: `stage_hunk_refuses_stale_header` in Task 5.
2. **Repo with no commits yet (unborn HEAD).** Expected: Changes tab lists files, staging and unstaging work, History shows "No commits yet". Tests: `status_on_unborn_repo` (Task 2), `unstage_file_on_unborn_repo` (Task 5), `history_on_unborn_repo_is_empty` (Task 6).
3. **Files with CRLF line endings or no trailing newline.** Expected: staging or discarding one hunk leaves every other byte of the file exactly as it was. Test: `hunk_ops_preserve_crlf_and_missing_newline` in Task 5.
4. **Binary or non-UTF-8 files.** Expected: shown as "Binary file, no preview" with sizes, never a panic or garbled text; still stageable and discardable as a whole file. Test: `binary_file_diff_reports_sizes` and `non_utf8_text_is_lossy_not_panic` in Task 3.
5. **A recent repo was moved or deleted, or the open repo disappears.** Expected: recent list drops missing entries on load; opening a non-repo folder shows "Not a Git repository: <path>"; no crash. Tests: `recent_drops_missing_paths` and `open_non_repo_errors` in Task 1.

### Task 4: Side-by-side rows and word-level highlight

**Files:**
- Create: `src/sbs.rs`, `tests/sbs_test.rs`

**Interfaces:**
- Consumes: `Hunk`, `DiffLine`, `LineKind`.
- Produces:
  - `pub struct Seg { pub text: String, pub changed: bool }`
  - `pub struct Cell { pub no: u32, pub kind: LineKind, pub segs: Vec<Seg> }`
  - `pub enum Row { HunkHeader { hunk_index: usize, header: String }, Line { left: Option<Cell>, right: Option<Cell> } }` (`None` side renders as striped filler).
  - `pub fn build_rows(hunks: &[Hunk]) -> Vec<Row>`

Pairing algorithm (not fixed by signature): within each hunk, walk lines; a run of consecutive Removed lines followed by a run of Added lines is paired index by index (removed[i] with added[i]); leftovers get `None` on the other side. Context lines put the same text on both sides with their own numbers. For each paired Removed/Added cell, compute word segments with `similar::TextDiff::from_words` (or `from_chars` when the line has fewer than 3 words) and mark non-equal segments `changed: true`. Unpaired lines get one segment, `changed: false`.

### Task 5: Stage, unstage, and discard (file and hunk)

This task loses user work if wrong. Test thoroughly.

**Files:**
- Create: `src/stage.rs`, `tests/stage_test.rs`

**Interfaces:**
- Consumes: `FileDiff`, `Hunk`, `DiffTarget`, `file_diff`, `CoreError::Stale`.
- Produces:
  - `pub fn stage_file(repo: &Repository, path: &str) -> Result<()>` (deleted in workdir: `index.remove_path`; else `index.add_path`; then `index.write`).
  - `pub fn unstage_file(repo: &Repository, path: &str) -> Result<()>` (`repo.reset_default(Some(head_commit.as_object()), [path])`; unborn HEAD: `index.remove_path` + write).
  - `pub fn discard_file(repo: &Repository, path: &str) -> Result<()>` (untracked: `std::fs::remove_file`; tracked: `checkout_index` with `force()` and `path(path)`, which discards only unstaged changes and keeps staged ones).
  - `pub fn stage_hunk(repo: &Repository, path: &str, hunk_index: usize, expected_header: &str) -> Result<()>`
  - `pub fn unstage_hunk(repo: &Repository, path: &str, hunk_index: usize, expected_header: &str) -> Result<()>`
  - `pub fn discard_hunk(repo: &Repository, path: &str, hunk_index: usize, expected_header: &str) -> Result<()>`

Hunk approach: build the same `git2::Diff` that `file_diff` used for that side (unstaged: index to workdir; staged: HEAD to index), with `reverse(true)` for unstage and discard. First recompute hunks and compare `hunks[hunk_index].header` with `expected_header`; on mismatch or missing index return `CoreError::Stale` and change nothing. Then `repo.apply(&diff, location, Some(&mut opts))` where `opts.hunk_callback` returns true only for the `hunk_index`-th hunk (count calls). Locations: stage = `ApplyLocation::Index`, unstage = `Index`, discard = `WorkDir`. Untracked file `stage_hunk` delegates to `stage_file` (whole file is one hunk). Note the reversed diff's hunk header differs from the forward one: compare `expected_header` against the forward diff, apply the reversed one; hunk order is the same.

  - `pub struct Controller` with `pub fn spawn(recent_file: PathBuf, emit: impl Fn(Event) + Send + 'static) -> Controller` and `pub fn send(&self, cmd: Command)`. Behavior rules (decided here):
- `OpenRepo`: open, touch + save recent, emit `RepoOpened`, `Status`, first `History` page (append false), `Diff(None)`. Error emits `Error(msg)` and keeps the previous repo.
- `Refresh`: re-emit `Status`; re-read history head and emit `History { append: false, new_ids }` where `new_ids` are commits not seen before (empty on first load); if Selection is a Range whose head was the old HEAD, move head to new HEAD and re-emit `Range` and `Files`; re-emit `Diff` for current selection, or `Diff(None)` and Selection::None if the file is gone.
- Stage/unstage/discard commands: run, then do a `Refresh`. `CoreError::Stale` emits `Error("File changed, refreshed. Try again.")` then `Refresh`.
- Selecting a Commit or Range with `path: None` emits `Files` and auto-selects the first file.
- Range `commit_count` = commits reachable from head and not from base.
